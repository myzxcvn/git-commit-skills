# Git 安全检查

## 提交候选

先检查 git status、git diff 和 git diff --cached。未跟踪文件需要单独检查。部分暂存文件同时存在两类改动，不能直接整文件 add。

普通 git commit 会提交整个 Index，而不是最后一次 add 的文件。任何无关暂存内容都应阻止普通提交，不自动取消暂存或使用 stash。用户明确要求提交整个暂存区时，按该范围处理，仍需检查敏感信息。

必要时用 git write-tree 记录已核对候选的树 ID，验证后重新比较；它不是锁，仍需在提交前检查状态，提交后可用 git rev-parse HEAD^{tree} 核对实际树。出现偏差立即停止，不擅自 amend/reset。只读消息生成任务不运行会写入对象的命令。

## 特殊状态

使用 git status 和 git rev-parse 检查仓库状态；需要查看状态文件时通过 git rev-parse --git-path 获取路径，不假定 .git 是目录。Merge、Rebase、Cherry-pick、Revert、bisect、冲突和锁定等状态不作为普通提交处理。检查失败或状态不明时停止。

## 验证范围

工作树测试可能依赖未暂存文件、未跟踪生成物或旧构建产物。确认依赖与候选一致；必要时在独立环境重建候选并使用正确工具链。不能安全隔离时报告限制，不宣称候选已通过。不得为隔离测试修改用户已有工作区或 Index。

## 推送范围

核对 git remote get-url --push、实际远端分支 SHA 和本地 HEAD；必要时经授权获取远端提交对象，再用 git log <remote-sha>..HEAD 及祖先关系检查完整范围。远端分支不存在时，确认新建分支和所有将发布的历史都获授权。远端跟踪引用可能过期，不单凭它判断。

使用明确的 remote 和分支 refspec，不默认推送标签或其他分支。普通 push 也可能触发配置的额外行为，应核对相关配置。远端发生变化或检查不通过时停止，不强推。

CI 查询应有有限次数或时间预算，不能查询或尚未结束就报告实际情况。
