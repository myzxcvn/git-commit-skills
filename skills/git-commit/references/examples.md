# 提交消息示例

以下仅示意表达，不能据此推断实际改动。

| 场景 | 示例 |
| --- | --- |
| 缺陷 | [core] 修复定时器溢出 |
| 性能 | [core] 减少调度队列扫描 |
| 构建 | [build] 启用 LTO |
| 依赖 | [deps] 更新 fmt |
| 测试 | [tests] 覆盖事件队列满载 |
| 文档 | [docs] 补充线程安全约束 |

避免“进一步优化相关逻辑”等空泛措辞；明确对象和变化，但不为追求具体而编造实现细节。

项目使用其他格式时沿用其规范，例如 `fix(timer): handle counter overflow` 或 `sched: Fix duplicate dispatch`。

复杂改动可以补充非显然的原因：

```text
[core] 使用就绪位图调度事件

避免每次分发扫描未就绪对象。
```

不兼容变更需要说明影响：

```text
[config] 将 timeout 单位改为毫秒

旧配置中的秒值需要转换后使用。
```

只有实际关联的问题才使用 Bug: 或 Fixed:；只有实际执行且有记录价值的验证才使用 Test:，并注明失败或局部验证等限制。目标仓库的页脚格式优先。
